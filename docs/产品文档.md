## 快速部署指南

> [!NOTE]
> 本指南从插件的部署开始写起。前置条件：已安装 AstrBot 并能访问其 WebUI——AstrBot 的安装与基础配置请参考 AstrBot 官方文档，不在本指南范围内。

### 开始之前：确认硬件条件

插件需要驱动一个真实浏览器在抖音网页版上收发消息，对资源的要求不低。动手之前，请先对照下表确认你的部署环境达标，不达标请走远程浏览器路线（见[如何判断自己适合本地浏览器还是远程浏览器](#如何判断自己适合本地浏览器还是远程浏览器)）。

**本地直接运行浏览器**

| | 最低配置 | 推荐配置 |
|---|:---:|:---:|
| **CPU** | 4 核 | 8 核 |
| **内存** | 4 GB | 8 GB |
| **硬盘（剩余空间）** | 10 GB | 20 GB |

**远程运行浏览器**

| | 最低配置 | 推荐配置 |
|---|:---:|:---:|
| **CPU** | 2 核 | 2 核 |
| **内存** | 2 GB | 4 GB |
| **硬盘（剩余空间）** | 1 GB | 10 GB |

> 以上要求已包含 AstrBot 本身的资源消耗，无需另行加码。

### 安装必装依赖：Node.js 与 Playwright

> [!IMPORTANT]
> **Node.js（20+）和 Playwright 是必装项**，缺一不可：Node.js 是插件浏览器运行时的宿主，Playwright 负责驱动浏览器。两者都没装，插件无法工作。

**第 1 步：安装 Node.js 20+**

- **Windows**：`winget install OpenJS.NodeJS.LTS`，或到 [nodejs.org](https://nodejs.org) 下载安装包

- **macOS**：`brew install node`

- **Linux（Debian / Ubuntu 系）**：

  ```bash
  curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
  sudo apt-get install -y nodejs
  ```

- **Linux（RHEL / CentOS / Alma / Rocky / 阿里云 Linux 系）**：

  ```bash
  curl -fsSL https://rpm.nodesource.com/setup_22.x | sudo -E bash -
  sudo dnf install -y nodejs
  ```

- **Linux（Arch 系）**：`sudo pacman -S nodejs`

- **macOS / Linux 兜底方案（nvm）**——不依赖系统包管理器，随时可以拿到最新版：

  ```bash
  curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
  ```

  执行完后**重新打开一个终端**（让 nvm 命令生效），然后安装 LTS 版：

  ```bash
  nvm install --lts
  ```

> [!WARNING]
> **Linux 用户注意：nvm 或手动解压安装的 Node，AstrBot 服务进程可能看不见。** AstrBot 通常以 systemd 服务运行，其 PATH 只包含系统目录（`/usr/bin`、`/usr/local/bin` 等）；nvm 和手动解压的 node 只存在于你的交互终端环境里。**插件会自动搜索常见安装位置**（nvm 默认目录、`/usr/local/node-*`、`/usr/local/lib/nodejs/*`、`/opt/node*` 等），多数情况无需处理。若仍检测不到，两种解法任选其一：
> 1. **软链到系统路径（推荐，无需重启）**：
>    ```bash
>    ln -sf "$(dirname "$(readlink -f "$(which node)")")/node" /usr/local/bin/node
>    ln -sf "$(dirname "$(readlink -f "$(which node)")")/npm"  /usr/local/bin/npm
>    ln -sf "$(dirname "$(readlink -f "$(which node)")")/npx"  /usr/local/bin/npx
>    ```
> 2. 把 node 的绝对路径填进插件配置的**「Node 程序路径」**（如 `/usr/local/node-v24.10.0-linux-x64/bin/node`）。

装完自检：终端执行 `node -v`，输出 `v20` 以上即合格；Linux 用户请同时确认上方的服务可见性问题（仅 nvm / 手动安装需要）。

**第 2 步：安装 Playwright**

打开插件的设置页（见下文[打开设置页](#打开设置页)），点击**安装插件浏览器依赖**按钮一键安装——Playwright 会装进插件自己的数据目录，不污染系统环境。也可以手动 `npm install playwright`，但一键安装是推荐路径。

### 选择路线：本地浏览器还是远程浏览器

> [!NOTE]
> **📱 想用远程浏览器的用户：浏览器装在远程主机上，本机不装浏览器。** 但 **FFmpeg 仍需装在本机**——远程主机上的视频压缩偶尔失败时，会由本机 FFmpeg 兜底接管；安装方法沿用下节中的 FFmpeg 部分。完成后请直接跳转[远程浏览器部署指南](#远程浏览器部署指南)。
> **💻 想用本地浏览器的用户：继续安装下面的依赖。**

> [!WARNING]
> **说明：Windows / macOS 环境的本地浏览器模式未经测试。**
>
> 1. 目前只有 Linux 环境经过了完整验证。Windows / macOS 用户可以自行尝试本地浏览器模式是否可用；如不可用，建议转到[远程浏览器部署指南](#远程浏览器部署指南)。
> 2. 如果希望尽快适配 Windows / macOS 的本地浏览器模式，你可以提供一台已装好 AstrBot 和抖音Agent 插件的电脑供作者远程测试——这将大幅加快适配进度，你也将成为内测用户并登上项目的鸣谢名单。
> 3. 不想等待适配的话，你也可以在本机内部搭建"远程浏览器"：Windows 用户可以使用 WSL 或 VMware 等虚拟机；macOS 用户可以使用 Container Machine 等项目。浏览器跑在这些虚拟环境里，插件按远程浏览器方式连接即可，不需要第二台实体机器。

### 本地浏览器用户：安装浏览器与 FFmpeg

**浏览器（Edge / Chrome / Chromium 三选一）**

- **本机已装 Edge 或 Chrome** → 跳过。插件自动探测并优先复用系统里已装的 Edge / Chrome，无需重复安装。
- **本机未装** → 两条路任选：
  - 手动安装 [Edge](https://www.microsoft.com/edge) 或 [Chrome](https://www.google.com/chrome)；
  - 在插件设置页点击**下载插件 Chromium**按钮一键下载独立 Chromium（装进插件数据目录，不接触系统环境）。

**FFmpeg 与 FFprobe**

两者用于视频下载后的压缩处理，**同一个包分发，装一个就全有**。

> **Linux 发行版家族速查**（拿不准自己属于哪个系就看这里）：
> - **Debian 系**：Debian、Ubuntu 及其衍生版，用 `apt` 安装软件
> - **RHEL 系**：Red Hat Enterprise Linux、CentOS、AlmaLinux、Rocky Linux、阿里云 Linux 等，用 `dnf` / `yum`
> - **Arch 系**：Arch Linux、Manjaro 等，用 `pacman`
> - 实在不确定：依次执行 `apt --version`、`dnf --version`、`pacman --version`，哪个有输出就是哪个系

- **Windows**：`winget install Gyan.FFmpeg`（装完重开终端让 PATH 生效），或到 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 下载解压并配置 PATH

- **macOS**：`brew install ffmpeg`

- **Linux（Debian / Ubuntu 系）**：

  ```bash
  sudo apt install -y ffmpeg
  ```

- **Linux（RHEL 系）**：ffmpeg 不在系统自带源里，先启用 EPEL 与 RPM Fusion 两个扩展源，再安装：

  ```bash
  sudo dnf install -y epel-release
  sudo dnf install -y --nogpgcheck https://mirrors.rpmfusion.org/free/el/rpmfusion-free-release-$(rpm -E %rhel).noarch.rpm
  sudo dnf install -y ffmpeg
  ```

- **Linux（Arch 系）**：

  ```bash
  sudo pacman -S ffmpeg
  ```

自检：`ffmpeg -version` 能输出版本号即成功。

### 配置插件

打开 AstrBot 的插件面板，找到**抖音Agent**插件，点击**配置**按钮打开配置面板。

**模型配置（核心）：**

1. **聊天模型提供商**：选择你在 AstrBot 中已配置、日常常用的那个模型提供商。
2. **视频处理方式**——按你模型的能力二选一：
   - 模型**支持**文本 / 视频 / 音频多模态输入 → 选 **直接交给聊天模型**。此时**不需要**再配置视频转述模型接口，该项留空即可。
   - 模型**不支持**多模态输入 → 选 **转述为文本**。此时**视频转述模型接口**必须选择一个**支持视频多模态**的模型（如 qwen3-vl 类），由它把视频内容转成文字交给聊天模型。

其余配置项按需调整，各项含义与推荐值见[插件配置项说明](#插件配置项说明)章节。

### 打开设置页

打开 AstrBot WebUI，点击左侧栏的**抖音Agent**面板进入接入设置页。

- **本机浏览器用户**：直接继续往下操作。
- **远程浏览器用户**：请先确认远程浏览器已成功连接并被抖音Agent 识别到（设置页会显示浏览器连接状态），未连接请先解决连接问题。

**本地浏览器 Linux 用户专用：启动虚拟屏（远程浏览器用户与 Windows / macOS 用户跳过本节）**

> [!NOTE]
> **远程浏览器用户**的虚拟屏在**远程主机**上，由[远程浏览器部署指南](#远程浏览器部署指南)负责搭建——本节的两个一键按钮在远程模式下不会出现在设置页，无需操作。



在 Linux 上，插件的浏览器统一运行在专属**虚拟屏**（Xvfb）中——与你真实的桌面环境无关，桌面上不会出现浏览器窗口，也就不存在"浏览器窗口被最小化 / 被遮挡"的问题。首次使用分两步：

1. 点击**一键安装虚拟屏套件**按钮，安装 Xvfb + x11vnc + noVNC（体积只有几 MB，不需要安装任何桌面环境）。
2. 安装成功后，点击**一键启动 noVNC**，再点击状态区出现的**打开虚拟屏观察窗**链接（默认 `http://127.0.0.1:6080/vnc.html`）——观察窗组件只监听本机回环地址，**不暴露公网**。在这个网页里你就能看到并操作虚拟屏桌面，后续扫码登录都在这里完成。

观察窗的访问方式：

- **浏览器与服务器同机**，或**通过 SSH 隧道**（`ssh -L 6080:127.0.0.1:6080`）访问服务器时，链接直接可用；
- **远程直接访问**需要一条从 AstrBot 对外域名到 6080 的反向代理路径（由部署侧的 nginx 等完成）——AstrBot 插件接口暂不支持 WebSocket 路由，RFB 流量无法完全寄生在 AstrBot 自身端口下，"零新增端口"需要平台能力或反代配合。

带桌面的 Linux 用户也可以改用本地 VNC 客户端连接 `127.0.0.1` 查看虚拟屏（可选，效果与 noVNC 网页等同）。

**观察窗（noVNC 网页 / VNC 客户端窗口）随时可以关闭或最小化，完全无副作用**——它只是一个观察窗，浏览器活在虚拟屏里，不受观察窗状态影响。

### 登录抖音并绑定会话

**1. 打开登录窗口**

在设置页点击**打开登录窗口**按钮：

- 本地浏览器的 Linux 用户 → 浏览器窗口会出现在**虚拟屏**里，通过 noVNC 观察窗（或本地 VNC 客户端）查看和操作；
- 远程浏览器用户 → 浏览器窗口出现在**远程主机的虚拟屏**里，通过远程主机一侧的 noVNC 观察窗查看和操作（访问方式见[远程浏览器部署指南](#远程浏览器部署指南)）；
- Windows / macOS 用户 → 桌面上会直接弹出插件的专用浏览器窗口。

**2. 登录机器人的抖音账号**

在弹出的窗口中**扫码**或用**账号密码**登录**机器人的抖音账号**（注意是机器人要用的号，不是你自己的号），完成可能出现的验证码。

登录成功后会跳转到抖音首页——如果你看到的是**抖音精选**页面，**这是预期行为，不是 bug**：抖音官方已将网页版首页重定向到抖音精选，插件正常以这个页面作为常驻工作页。

**3. 进入目标私信会话**

在同一窗口点击抖音的**消息**入口，再点开**你要绑定的那个用户的私信界面**，直到能看见**聊天记录和输入框**（只停在首页或消息列表是不够的）。

**4. 确认会话里有双向消息**

确认这个会话里**双方都发过消息**（有来有回）。如果是刚建立的新会话、聊天记录是空的，请先**互相各发送至少一条消息**——Agent 需要靠"你的消息在右、对方的消息在左"的双向记录来确定收发方向，空会话会导致方向识别失败、绑定后无法正常回复。

**5. 绑定**

**不要关闭浏览器（或 noVNC 窗口）**，回到设置页点击**绑定当前会话**。

**6. 核对并开启回复**

绑定后设置页会显示**当前绑定的对象名称**——**核对正是你刚才那个会话对象**再继续；名称不对说明锚定错了会话，重新执行第 3~5 步。

确认无误后点击**开启回复**——Agent 正式上线。

> [!NOTE]
> **绑定只从绑定那一刻开始记录新消息**，绑定前的历史消息不会补录。所以验证插件是否正常，请绑定后发新消息测试，不要拿绑定前的旧消息当测试依据。

### 验证是否正常

按下面的顺序渐进验证，不要跳步：

1. **纯文字**：用你自己的账号（绑定的那个会话对象）发一条**新的纯文字消息** → 确认 Agent 能正常回复。文字链路通了，说明绑定、方向识别、模型配置全部就位。
2. **分享图文 / 视频**：再分享一条媒体内容 → 验证 Agent 能读图 / 转述视频后回应。

两个说明：

- **操作成功但设置页状态没变** → 点设置页右上角的**刷新状态**，或直接刷新整个网页即可。**不要**因此反复绑定或重开浏览器窗口——那只会平添风险，状态不同步多数只是页面没刷新。
- **Agent 读取分享内容时**，可能临时打开一个作品标签页，正常结束后会自动关闭这个临时页。**请保留原来的私信页**——看到浏览器跳到作品页**不代表私信接入断开**，也不需要你手动切回私信，Agent 自己会处理。

### 部署完成后的收尾

- **Linux 用户**：验证通过后可以点击**关闭 noVNC**释放观察层资源——观察窗本来就是随时可关的，虚拟屏和浏览器继续运行不受影响；以后需要扫码或查看桌面时，随时重新一键启动。
- **Windows / macOS 用户**：没有虚拟屏，也用不上 noVNC 相关按钮。

> [!IMPORTANT]
> **Windows / macOS 本地浏览器用户请注意：不要关闭浏览器窗口，不要最小化，也不要让其它窗口把它完全遮挡**——抖音已屏蔽插件可用的 DOM 级事件，插件的自动化操作依赖真实鼠标点击与页面的正常渲染，窗口关闭、最小化或被完全遮挡后，Agent 将无法正常工作（窗口保持在后台但不被完全挡住是可以的）。Linux 用户不受此条约束——浏览器运行在虚拟屏里，你的桌面上没有浏览器窗口。

## 如何判断自己适合本地浏览器还是远程浏览器

先理解两种模式的本质区别：

- **本地浏览器**：浏览器和 AstrBot 跑在同一台机器上——结构最简单，维护最方便。
- **远程浏览器**：浏览器跑在另一台机器上（通常是家里的宽带电脑），服务器只跑 AstrBot，两者通过隧道连接——部署见[远程浏览器部署指南](#远程浏览器部署指南)。

逐条对照下面四种情况：

1. **看配置**：服务器配置足够高（满足[硬件要求](#开始之前确认硬件条件)），选本地浏览器，维护方便；配置较低、不满足性能要求，选远程浏览器——低配服务器可以继续用，节约成本。
2. **看 CPU 年代**：核心数虽然满足 4 核要求，但 CPU 太老、主频太低，实测浏览器操作卡顿的，建议选择远程浏览器模式。
3. **看同机业务**：服务器上还跑着其它业务（网站、数据库、别的机器人等）——Agent 刷视频时会频繁操作浏览器和 FFmpeg，CPU 占用会激增甚至打满，可能影响其它业务，这种情况建议选择远程浏览器。
4. **看 IP 归属**：服务器是机房 IP（云服务器基本都是）而非家用 IP——抖音对机房 IP 更容易触发风控甚至封号，建议选择远程浏览器模式（浏览器跑在家里，走家用宽带 IP 出口，对抖音风控更友好）。服务器用的是家用宽带（比如家里的 NAS、旧电脑），建议选择本地浏览器模式。

> 速记：**配置足、CPU 不老、机器独占、家用宽带**——四条全满足，闭眼选本地；任何一条不满足，远程浏览器更省心。

## 插件配置项说明


在 AstrBot WebUI 的插件面板中打开抖音Agent 的**配置**面板即可修改以下各项。**标注"推荐不动"的项保持默认即可**，日常使用只需要关心基础开关和模型两组。

### 基础开关

| 配置项 | 默认 | 说明 |
|---|---|---|
| 启用抖音私信接入 | 开 | 私信功能总开关。开启后插件处理私信、群聊等消息；关闭后不再接收和回复私信，但搜索视频、刷视频、评论等工具仍可被 Agent 调用。分享依赖私信会话故不可用，Agent 可改为把视频链接通过 QQ 等其他平台发给你 |
| 自动回复已绑定的私信 | 关 | 开启后 Agent 对绑定会话的新消息自动回复（对应设置页的**开启回复**按钮） |
| 启用私信白名单 | 开 | 开启后只处理白名单内的会话；关闭后可处理当前打开的其他私信 |
| 私信白名单 | 空 | 填写会话标识，每行一个。首次绑定时自动添加该联系人，一般无需手动填写；清空后不接收任何人的消息。可用 `/抖音 状态` 查看已绑定标识，`/抖音 查看` 查看当前会话标识。注意保持目标私信在插件的专用浏览器窗口中打开 |

### 模型

| 配置项 | 默认 | 说明 |
|---|---|---|
| 聊天模型提供商 | 空 | 用于处理聊天消息的模型。若未开启独立转述，该模型也会同时处理音视频内容；留空则跟随 AstrBot 当前配置的默认聊天模型。可与视频转述模型独立配置 |
| 视频处理方式 | 转述为文本 | 聊天模型支持音视频等多模态时，建议选"直接交给聊天模型"，体验更一致；聊天模型不支持多模态或仅支持图片模态时，选"转述为文本"——视频先交转述模型转成文字，再由聊天模型生成回复 |
| 视频转述模型接口 | 空 | "视频处理方式"为"直接交给聊天模型"时留空即可；为"转述为文本"时，此处须选择能读取**视频和音频文件**的模型 |
| 视频转述要求 | 内置默认 | 与视频文件一并交给转述模型的系统提示词。无特殊需求保持默认即可；如自行编写，请在完成后实测确认模型输出符合预期 |
| 视频转述等待上限秒数 | 90 | 转述超时上限，超过该时长直接判定转述失败，不再等待结果。请根据所选用模型的处理速度合理配置 |
| 附带独立音轨核对 | 开 | 开启后作品被拆分为画面与音轨：画面走"视频转述模型接口"，音轨走"音频转述模型接口"，两路并行、结果合并。关闭时整条视频直接输入"视频转述模型接口"，不拆分 |

符合以下任一情况时，建议开启本项：

1. 视频转述模型只支持视频模态，不支持音频模态；
2. 视频转述模型虽支持音频模态，但输入视频文件时只识别画面、不识别声音（很多多模态模型的通病）；
3. 视频转述模型对音频识别能力差、经常出错。

不符合上述情况时可按需选择：开启后转述质量更高，关闭后 token 成本更低。
| 音频转述模型接口 | 空 | 开启"附带独立音轨核对"时，本项需选择支持音频模态的大模型，最好选择 ASR 等专用模型；未开启时留空即可 |

> [!WARNING]
> "使用的人格 ID"如果选择了与其它机器人不同的人格，同时又开启了"**关联已有对话与共享上下文**"，可能造成模型记忆错乱、OOC 等情况——建议与关联的已有对话保持一致。未开启关联功能则无需顾虑，可按需随意配置。

| 启用 WebUI 手动绑定 | 关 | 开启后执行「绑定」时直接使用下方信息，无需先在浏览器打开会话 |

| 手动绑定：对象显示名 | 空 | 浏览器恢复会话时按名称定位，需与会话列表一致 |
| 手动绑定：会话唯一 ID | 空 | `0:1:…` 格式；可选，填写后定位更精确 |
| 手动绑定：目标是群聊会话 | 关 | 目标为群聊时开启 |

> 完整的字段定义以仓库根目录的 [`_conf_schema.json`](../_conf_schema.json) 为准，本文档与其同步维护。

## WebUI 配置项说明


插件在 AstrBot WebUI 左侧的**抖音Agent**面板（接入设置页）分三个标签页和若干折叠区块：

### 会话接入（标签页一）

#### 登录与绑定

绑定向导按六步清单推进：模型确认 → 打开登录窗口 → 进入目标会话 → 绑定当前会话 → 核对对象 → 开启回复。

- **打开登录窗口**：用于在未登录抖音账号时，打开专属登录窗口以供登录。插件启动时一般会自动打开，不需要手动操作。
- **绑定当前会话**：绑定浏览器窗口当前打开的私信会话，绑定后自动加入白名单。
- **开启回复**：抖音Agent 开始自动处理并回复消息。
- **暂停回复**：抖音Agent 暂停自动处理回复，一般用于需要手动维护网页的场合，比如手动解除验证码。
- **重开登录窗口**：登录完成后不慎关闭了浏览器窗口时，用本按钮重开。重开后保持登录状态，并自动打开绑定的私信窗口。
- **刷新抖音会话列表**：刷新私信的全部会话列表，展示在下拉框中。
- **打开所选会话**：打开下拉框中指定的会话。

#### 私聊设置

- **在白名单内自动切换私聊与群聊**：开启后自动切换处理白名单内全部会话，关闭时只处理当前窗口的会话。本开关与插件配置内同步。
- **抖音账号显示名**：识别不到时可手动填写，方便机器人判断聊天方向以及是否 @ 了自己；一般不需要填写。

#### 群聊设置

- **允许绑定抖音群聊**：群聊功能总开关。关闭后工具调用与私聊功能不受影响；开启后可使用群聊功能。本配置与插件配置同步。
- **群聊回复方式**：见[插件配置——群聊回复方式](#群聊测试中)。
- **机器人在群内的昵称**：识别不到时可手动填写，方便机器人判断聊天方向以及是否 @ 了自己；一般不需要填写。
- **群聊读取所选 QQ 对话与记忆**：见[插件配置——群聊读取所选 QQ 对话与记忆](#群聊测试中)。

#### 浏览器与运行环境（折叠区）

- **登录浏览器**：见[插件配置——登录浏览器](#浏览器与运行环境)。
- **安装插件浏览器依赖**：点击后自动安装 Playwright。请确保以 root 权限运行 AstrBot 与插件，否则会失败。
- **下载插件 Chromium**：点击后自动安装 Chromium 浏览器。请确保以 root 权限运行 AstrBot 与插件，否则会失败。
- **安装虚拟屏套件**（仅 Linux 本地模式显示）：一键安装 Xvfb + x11vnc + noVNC（共几 MB），安装可能需要几分钟并请求 sudo 权限。
- **启动 noVNC / 关闭 noVNC**（仅 Linux 本地模式显示）：开关网页观察窗——开启后用浏览器访问 `http://<本机IP>:6080/vnc.html` 即可看到并操作虚拟屏里的浏览器（登录扫码、处理验证码都用它）；随时关闭，不影响后台运行。远程浏览器模式下无需本项（虚拟屏在远程主机上）。

### 上下文与记忆（标签页二）

#### 关联已有对话与共享上下文

- **读取已关联渠道的近期上下文**：开启后自动读取已关联的 QQ 等渠道上下文；关闭后只读取抖音平台上下文。
- **最多读取多少条消息 / 会话活跃时限（小时） / 每条消息最多读取多少字 / 一次共享的总字数上限**：见[插件配置——上下文关联](#上下文关联)。
- **查找已有对话**：搜索已有对话的入口，一般可用 QQ 号等关键词进行搜索。
- **选择已有 AstrBot 对话**：选择你想关联的其它平台对话，然后点击**关联所选对话**完成关联。
- **双向参考近期上下文**：开启后不仅抖音会参考其它平台上下文，其它平台也会参考抖音的上下文。
- **参考长期记忆**：本功能依赖 [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 插件。开启后抖音端会参考你在其它平台的长期记忆（只读，不改动对方记忆）。

  记忆互通分两档：

  - **抖音端只读参考**：正确安装 LivingMemory 即可用，无需任何额外配置。
  - **双端互通（QQ 端也能想起抖音里聊过的内容）**：需要手动操作 LivingMemory 的两个开关——在 **AstrBot Dashboard → 插件 → LivingMemory → 设置页 →「访问与隔离」分组**中，把**记忆作用域模式**改为 `user`，并开启**跨适配器共享用户记忆**。身份对齐无需手工配置：关联对话时本插件自动完成，解除关联自动撤销。未配置这两个开关时，插件会把抖音端对话以镜像方式写入关联对话的记忆（效果等价）；配置后自动切换为 LivingMemory 原生互通，镜像退场、记忆不重复。修改开关后请记得点击页面底部的保存。

> [!WARNING]
> **风险提示**：上述两个开关是 LivingMemory 的**全局设置**，改动会影响它在**所有平台**（不止抖音）的记忆行为。已产生的旧记忆无需迁移、仍可召回；但改为用户作用域后，**群聊场景的召回会按发言者身份拉取其个人记忆——发言者在其它对话里的记忆内容可能出现在群聊回复中**（此为 LivingMemory 现阶段的行为，介意请谨慎开启）。本插件自身对群聊保持只读，不会把群成员发言写入任何个人记忆。操作前建议备份 LivingMemory 数据目录（`plugin_data/astrbot_plugin_livingmemory/`）。

## FAQ

### 部署与平台

**Q：Windows / macOS 上本地浏览器模式能用吗？**

未经测试，不确定。可以自行尝试；不可用的话建议转到远程浏览器模式。Windows 可用 WSL 或 VMware 在本机搭"远程浏览器"，macOS 可用 Container Machine 等项目——不需要第二台实体机器。愿意提供测试机器的用户可联系作者，成为内测用户并登上鸣谢名单（详见[快速部署指南](#快速部署指南)中的说明）。

**Q：为什么我的 Linux 桌面上看不到浏览器窗口？**

这是设计行为。插件在 Linux 上把浏览器统一放在专属虚拟屏（Xvfb）中运行，需要查看或操作时通过 noVNC 网页或本地 VNC 客户端连接；观察窗随时关闭、最小化都没有任何影响。

### 预期行为（不是 bug）

**Q：登录后跳到了"抖音精选"，是不是出 bug 了？**

不是。抖音官方已将网页版首页重定向到抖音精选，这是预期行为，插件以该页面作为常驻工作页。

**Q：绑定后，之前的聊天记录会被 Agent 读到吗？**

不会。绑定只从绑定那一刻开始记录新消息，旧消息不会补回。请绑定后发新消息测试。

**Q：系统静音会影响识别声音吗？**

不会。声音从实际下载的文件中提取，不录制电脑正在播放的声音——系统静音、浏览器静音都不影响识别。

**Q：可以把浏览器窗口最小化吗？可以在它前面叠其它窗口吗？**

Linux 用户没有这个问题——浏览器运行在虚拟屏里，你的桌面上没有浏览器窗口。Windows / macOS 本地浏览器用户则不行：抖音屏蔽了插件可用的 DOM 级事件，插件的自动化操作依赖真实鼠标点击和页面正常渲染，窗口最小化后页面进入节流状态；Windows 下窗口被**完全遮挡**也会被浏览器判定为最小化（部分可见没问题）。请保持窗口打开、不最小化、不被完全遮挡——挂在后台不被挡住是可以的。

**Q：操作明明成功了，设置页状态却没更新？**

点设置页右上角的**刷新状态**或刷新整个网页。不要反复绑定或重开浏览器窗口。

**Q：想让 QQ 端也能想起抖音里聊过的内容，为什么还要去 LivingMemory 里改开关？有风险吗？**

「参考长期记忆」只负责抖音端的只读参考，正确安装 [LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 即可用。要让双端互通，需在 **AstrBot Dashboard → 插件 → LivingMemory → 设置页 →「访问与隔离」分组**把**记忆作用域模式**改为 `user`、开启**跨适配器共享用户记忆**——身份对齐由本插件自动完成，改完记得点保存。风险在于这两个开关是 LivingMemory 的全局设置，会影响所有平台的记忆行为：改为用户作用域后，群聊召回会按发言者身份拉取其个人记忆，发言者在其它对话里的内容可能出现在群聊回复中，介意请谨慎开启，操作前建议备份 LivingMemory 数据目录。不配置也能用——插件会把抖音对话以镜像方式写入关联对话的记忆，效果等价。详见[WebUI 配置项说明——上下文与记忆](#关联已有对话与共享上下文)。

### 故障排查

**Q：登录成功了，却一直读不到消息？**

按顺序逐条检查：

1. 确认是在**插件自动弹出的窗口**中登录的，不要手动打开抖音网页登录——你平时用的浏览器即使已登录，也和插件没有关系。
2. 确认没有登错账号；更换账号需要重新走一遍绑定流程。
3. 确认双方互相关注关系正常、双方都没有被封号。
4. 如果浏览器停留在验证码或安全验证页面，请手动帮你的 Agent 完成验证。
5. 如果显示"正在处理消息"，请耐心等待——模型正在处理你之前分享的或它主动刷到的视频，你的新消息会排在队列后面依次回复。
6. 点**刷新状态**可以查看进度，不要在处理中重复绑定或重开窗口。处理失败时按页面给出的错误提示处理；不要把"回复开关已开启"当作已完成连接。

**Q：只读出了标题，或者视频转述失败？**

按顺序逐条检查：

1. 确认你的模型接口**真的支持视频模态输入**，而不是只支持图片模态（不少"多模态"模型其实只有图片输入）。
2. 检查你的 API Key 余额和限流情况。
3. 检查你的 IP 是否被抖音风控或屏蔽。
4. 以上三者都没问题时，可以作为 bug 反馈（GitHub Issues 或社区群）。

**Q：为什么评论没有发出去？**

按顺序逐条检查：

1. 检查评论开关是否正确打开。
2. 检查作品是否已被实际读取。
3. 检查抖音是否要求验证、账号是否被封禁。
4. 页面控件识别不明确时会停止提交。没有收到评论 ID 的结果会记为**失败或未知**，不能当作已发出，也不会自动重发（防止重复评论，属设计行为）。

**Q：我的配置满足要求，为什么浏览器操作非常卡顿？**

按顺序逐条检查：

1. 检查你的 CPU 睿频能否达到 3 GHz 以上——浏览器除了对核心数有要求，对**频率**也有要求。
2. 在第 1 条满足的情况下，检查服务器的物理宿主机是否开启了**性能模式**而非节能模式；是否开启了 C-State、是否限制了 C-State 级别。请打开并放开 C-State 级别限制，让闲置核心能够睡眠——这样繁忙核心才能睿频到更高频率。
3. 检查是否有其它业务在争抢资源。
4. 如果是云服务器，检查是否为**独享型实例**。共享型实例存在超分，会争抢 CPU 性能（典型如经济型云服务器、突发型实例、轻量应用服务器）。
5. 删除浏览器里的一切插件，用纯净的浏览器运行。
6. 如果以上都确认没问题——睿频达标、无业务争抢、也是独享型实例——而你的云服务器来自十八线小厂，请立即拨打 IDC 服务商所在地区号 + 12345，投诉他们虚假宣传，退一赔三。

**Q：终端里 node 命令正常，插件却提示 Node.js 或 Playwright 未就绪？**

两种可能，按顺序排查：

1. **Node 对 AstrBot 服务不可见**——插件会自动搜索 nvm、`/usr/local/node-*` 等常见安装位置；装得比较冷门没被搜到时，软链到系统路径（`ln -sf` 三连，见[安装必装依赖](#安装必装依赖nodejs-与-playwright)中的警告框），或把绝对路径填进插件配置的「Node 程序路径」。
2. **Playwright 安装未完成**——安装按钮因网络中断后，界面会显示位置但状态仍是"未就绪"。重新点**安装插件浏览器依赖**即可（安装失败时会自动换国内镜像源重试）。手动补装也行：
   ```bash
   cd <AstrBot数据目录>/data/plugin_data/astrbot_douyin_agent/runtime/browser
   npm install --ignore-scripts --no-audit --no-fund --registry=https://registry.npmmirror.com
   ```

### 配置与进阶

**Q：为什么插件配置里有无头模式，但没有相关教程？**

不推荐使用。抖音已经屏蔽了绝大部分 DOM 事件，无头模式下极易出现频繁弹验证码或点击失效，因此教程不覆盖该模式。如果你有较好的解决思路，可以提供给作者，由作者进行尝试。
